# Pepper engineering contract

This is the single source of project rules for Claude Code and Codex. User instructions take precedence. Read the affected source before editing; live source wins over historical chat descriptions.

## UI and formatting
- Navigation order (by user decision 2026-10-03): Dashboard → 종목 분석 → 시장 온도계 → Watchlist → Portfolio → Journal → Leaderboard → Universe → Settings. Leaderboard and Universe open with a page guide that states the current UNIVERSE-2 scope, counts and classification rules.
- Brand: the Folio lockup (`public/folio-icon.webp` + `public/folio-wordmark.webp`, one shared height) with slogan `Fewer decisions. Greater conviction` and, on the loading page, the platform description beneath it. In the light theme (the app's only theme) the card icon carries a 3D tilt and layered shadow. The page-top brand shows only at >=1280 CSS px (desktop sidebar, iPad Pro landscape bar); narrower screens open with the menu button in the page header, and the menu drawer shows the brand sized to its width. The loading page ends with one small line: the Peppercorn Capital icon and name at equal height plus ©.
- DASHBOARD-FOCUS-1 (by user decision 2026-10-04; display/triage only, never changes the v1 leadership class, RS rank, stage or thresholds): the home is list-first and progressively disclosed. Order: 오늘의 리더 → 주도 섹터 → 시장 온도계 → collapsed ETF · 시장 탐색. The Focus List first applies the existing LEADER-LENS-1 filter state (growth-only remains the default when growth data is available), then orders daily-classified 핵심 주도·주도 후보·강세 전환 by top-20%-ranked industry group first, class priority core > candidate > turn, group rank, RS rank and 52W-high proximity. It keeps a strict maximum of two stocks per industry group and never backfills a thin market with extra names from the same group; one market shows at most 10, ALL shows at most 6 KR + 6 US. Rows are grouped under their industry-group rank so the top-down path is visible. Counts explicitly distinguish Focus from the broad v1 classes, and the full broad lists remain available. This funnel is not a new signal and needs no classification backfill or database write.
- MOBILE-DECISION-1 / UI-PRIMITIVES-1 (by user decision 2026-10-04): phone Dashboard follows a primary/secondary information hierarchy. Primary = market toggle, 오늘의 리더, compact 주도 섹터 decision list, 시장 온도계; search, long explanatory prose and dense multi-column sector metrics do not compete on the first phone viewport. Secondary tools (조정 중, 대형 주도주, momentum/live views, 시장 지표 and sector heatmap) sit behind disclosures; ETF · 시장 탐색 stays collapsed. `src/components/DecisionList.tsx` is the shared typed render primitive for ranked navigation surfaces: pages supply small view models (rank/title/meta/badge/value), while canonical detail tables and investment calculations stay separate. This is an SDUI-ready presentation boundary, not a server-controlled classification or data rule.
- MOBILE-ANALYSIS-1 (by user decision 2026-10-04): phone 종목 분석 keeps the price/benchmark chart and 한눈에 보기 as the primary decision surface. 비교, 주요 지표, 같은 산업 종목 and 상세 지표·공시는 grouped under one `상세 데이터` disclosure that starts closed at <=650 CSS px and open on wider screens. Adding a compare stock opens this disclosure automatically. The mobile drawer groups destinations as 핵심 (Dashboard, 종목 분석, 시장 온도계, Watchlist), 기록 (Portfolio, Journal), 전체 데이터 (Leaderboard, Universe, Settings); desktop navigation order is unchanged. This is presentation-only and never changes calculation, classification, stored records or data contracts.
- MOBILE-WORKSPACE-1 / MOTION-1 (by user decision 2026-10-04): phone Watchlist and Portfolio use the same primary/secondary hierarchy as Dashboard and 종목 분석. Primary = compact `DecisionList` rows with identity, stage/account and the few decision values; editing remains canonical in the existing grid behind a shared `ProgressiveDisclosure` labelled `전체 표 · 편집`. Wider screens keep the grid open and hide the disclosure summary. Tapping a compact row opens 종목 분석 when the ticker exists in the loaded universe. Common motion uses CSS tokens (`--motion-fast/base/sheet/ease`) for press, disclosure, dialog and drawer feedback; motion is user-triggered, short, and reduced to ~1 ms when `prefers-reduced-motion` is set. No workspace fields, persistence, ranking or live-price rules change.
- MOBILE-CATALOG-1 (by user decision 2026-10-04): phone Leaderboard and Universe use a summary-first catalog. Primary = the current market/search filter plus up to 20 compact `DecisionList` rows; Leaderboard shows class/stage and RS/20D, Universe shows exchange/group context. The canonical AG Grid remains unchanged behind `전체 표 · 모든 지표` / `전체 표 · 구성 정보`. Wider screens keep the full grid open and hide the disclosure summary. Compact rows open 종목 분석. Long Leaderboard/Universe rule guides stay available on wider screens but do not occupy the first phone viewport. No universe membership, rank, classification, filtering or refresh rule changes.
- MOBILE-JOURNAL-1 (by user decision 2026-10-04): phone Trading Journal is summary-first. Records with a ticker appear in compact `DecisionList` rows showing date, status, identity, current/realized value and buy price; the canonical editable AG Grid remains behind `전체 표 · 기록 편집`. Wider screens keep the full grid open and hide the disclosure summary. Tapping a compact record opens 종목 분석 when the ticker is in the loaded universe. Journal calculations, stored fields, workspace persistence and review semantics do not change.
- MOBILE-ANALYSIS-RECORDS-1 (by user decision 2026-10-04): the phone 종목 분석 page does not append the full editable analysis-record AG Grid to the primary reading flow. The canonical records grid is wrapped in the shared `ProgressiveDisclosure` as `종목분석 기록 · 목록`, starts closed at <=650 CSS px, stays open with its header hidden on wider screens, and automatically opens when an action explicitly navigates to the records section. The explanatory table note is hidden on phones. Record creation, auto fields, filed fields, delete behavior and persistence do not change.
- MOBILE-POLISH-1 (by user decision 2026-10-04): phone visual density is controlled by readability/touch ergonomics rather than by adding/removing decision logic. At <=650 CSS px, primary interactive controls target at least 44 CSS px, fixed bottom-nav items at least 52 px high, compact decision rows at least 64 px high, visible secondary/meta text on decision surfaces is kept around 10 CSS px or larger, and text inputs/selects/textarea render at 16 CSS px to avoid iOS Safari focus zoom. These overrides apply to the existing decision-first hierarchy only; they do not change content, calculations, ranks, persistence or breakpoints.
- IPAD-TOUCH-1 (by user decision 2026-10-04): iPad/touch layouts keep their existing responsive information density and navigation structure, but touch ergonomics match the phone system. At 651–1279 CSS px and touch-oriented 1280–1500 CSS px, primary navigation/menu controls target at least 44 CSS px, bottom-nav items at least 52 px high, form controls render at 16 CSS px, drawer rows at least 52 px high, and common disclosure/action controls receive tablet-safe hit areas. This does not convert iPad to the phone summary-first content model and does not change calculations, ranks, persistence, breakpoints or desktop layout.

## Analysis criteria
- Preserve the live classification source in `supabase/schema.sql` and functions; `src/App.tsx` has display fallback rules. `analysis/analyze.py` is a legacy/reference engine; `analysis/fundamentals/` is a separate SEC/DART PoC that writes artifacts only. Neither proves that the web app uses these values.
- Existing display fallback: core = trend pass, RS rank >=95, high distance >=-15%, RS 3M/6M >0. Candidate = trend pass, IBD-style estimate >=80, high distance >=-25%, RS 3M >0. Correction is a separate observation group. Never silently change thresholds during a UI edit.
- RS rank is not official IBD RS. Keep IBD estimate and its >=253-session history requirement explicit. 52W return uses 252 sessions; high distance uses available high history with source coverage disclosed.
- ETF-RS-1 measures each ETF's available 5D/20D/50D/120D/200D and legacy 1W/1M/3M/6M/12M returns against its market benchmark (US SPY; KR 226490 KODEX 코스피 since KR-BENCH-2, previously 069500 KODEX 200) on the same metric date. ETFs never enter the equity RS rank, the equity IBD ranking or the leadership class (핵심 주도·주도 후보·강세 전환; the app shows `해당 없음`). Missing source/benchmark history stays unknown.
- KR-BENCH-2 (by user decision, `supabase/migrations/*_kr_benchmark_instrument.sql` + `*_kr_benchmark_kospi.sql`, workflow `KR benchmark to KODEX 코스피 (production)`): every KR relative-strength value — equities in `recalculate_market_leadership()` and ETFs in `recalculate_etf_relative_strength()` — is measured against KODEX 코스피 (226490); US stays SPY. The universe scripts write `benchmark_ticker` 226490 for KR. Change the benchmark in both functions together.
- RECALC-TIMEOUT-1 (`supabase/migrations/*_recalc_statement_timeout.sql`): `service_role` has a 120 s `statement_timeout` so `recalculate-market` is not cancelled at the API's 8 s default. A failed recalculation leaves the newest `market_metrics` rows without RS rank, Trend Template and stage, which `leaderboard_view` shows as 중립 (leaders 0). `analyze.yml` skips a scheduled pre-open/post-close run that GitHub starts late inside the session, so an intraday bar is never stored as the day's close.
- ETF-SWING-1 (by user decision, `supabase/migrations/*_etf_swing_criteria.sql`, run inside `recalculate_etf_relative_strength()`): ETFs get an IBD-style estimate with the equity formula ranked among same-market ETFs (ETF-IBD-1; <253 sessions stays —), and the equity Trend Template, stage, verdict and action guide rules with the ETF-only RS rank (ETF-RS-RANK-1) in place of `rs_rank`. The classification CASEs are a copy of `recalculate_market_leadership()`; change both together and keep the parity checks in `supabase/tests/etf_rs.verify.mjs`.
- ETF-RS-RANK-1 (display, `src/lib/etfRank.ts`) ranks ETFs only against ETFs of the same market: the equity rank's weighted RS 1M/3M/6M/12M score (.30/.30/.20/.20, re-weighted over available periods) and round(1+98·cume_dist). It is stored as `etf_rs_rank`, never in `rs_rank`; an ETF without those RS inputs stays unranked (—). The dashboard ETF summary reuses `StockRows` with the same columns as 주도 종목 (the RS rank column shows `etf_rs_rank` for ETFs; the IBD-style estimate column shows the ETF-IBD-1 value).
- ETF-VALUE-1 (`supabase/migrations/*_etf_traded_value.sql`, step 4 of `recalculate_etf_relative_strength()`): `market_metrics.traded_value_20d` is the 20-session average of close × volume in the listing currency (ETFs since ETF-VALUE-1, every active instrument since VALUE-2); fewer than 20 sessions with volume stays unknown. `leaderboard_view` exposes it as a trailing column. This migration supersedes `*_etf_swing_criteria.sql`; never re-apply the older one.
- ETF-INDUSTRY-2 (display, `src/lib/etfIndustries.ts`, `src/lib/treemap.ts`): the dashboard `ETF 주도 산업` treemap heatmap is inside the collapsed `ETF · 시장 탐색` disclosure after 시장 온도계. ETFs are grouped by market and industry (Broad Market, Multi-Sector, Multi-Asset and unclassified excluded); tile area = the industry's summed ETF-VALUE-1, one map per market so KRW and USD are never compared; tile colour = median benchmark-relative RS for the selected period (5D/20D/50D/120D/200D/52W, default 20D) on a diverging red(+)/gray/blue(−) scale with period-specific thresholds; missing values stay out of sums and medians and an industry without trading value has no tile.
