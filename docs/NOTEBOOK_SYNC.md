# Account notebooks and reflections

Signed-in notebooks now use `notebook_entries`, keyed by authenticated owner and the original entry ID. Text/structured Tiptap JSON, photos, vector ink, dated revisions and reflection history remain together. Guest IndexedDB notebooks are never assigned to a signed-in account. The authenticated `notebook` function verifies the session with Auth and forwards the caller JWT to owner RLS; no service-role key is used.

A local save commits to IndexedDB with a durable pending entry before any upload. Reads precede uploads; reconnect, focus and a 30-second foreground timer retry. Matching remote versions acknowledge lost responses idempotently. Recorded ancestor revisions permit several offline edits to fast-forward; divergent branches and legacy same-ID edits are retained as a separate `기기에서 복원` page. Opening each device once is necessary to upload its existing account-local records. Backups remain available; no originals are deleted. Individual account notebook payloads remain bounded by the existing 18MB/1,000-page limit.

Research baskets sync per market+ticker mutation, retain server deletion markers, and expose known keys so an older device's migration cannot resurrect an already removed item. Original account-local cache keys remain compatible. Workspace lists refresh on focus/reconnect and every 60 seconds. Their durable per-account/per-resource IndexedDB outbox keeps failed writes until an exact mutation is acknowledged; cross-tab Web Locks serialize resource uploads where supported.

Journal captions flow below photos. Only one Home cover consumes each personal photo, with Journal priority, retaining the portrait two-column composition. Journey reviews have due/planned/completed filters and explicit result, decision (maintain/revise/close), lesson, next action and next date. Reviews append to history and preserve original note content; dirty dismissal still requires confirmation. Tiptap uses the existing pinned open-source StarterKit, with selected formatting state, expanded format controls, undo/redo and preserved photo/ink/backups.

Validation: `node supabase/tests/notebook.verify.mjs`; `tests/account-sync.spec.ts`, `tests/workspace-outbox.spec.ts`, existing lifetime/editorial/lifestyle tests; harness, build, identity, four-screen and full UI gates. Actual production database owner read/write, cross-owner isolation and stale-write rejection were verified inside a rolled-back synthetic fixture. No physical iPhone/iPad Safari or Pencil verification is implied.
